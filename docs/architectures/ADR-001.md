# ADR-001: Собственный сервер на Raspberry Pi с C++ HTTP API и единым веб-интерфейсом

- **Статус**: Proposed
- **Дата**: 2026-09-28
- **Тема**: Выбор архитектуры самостоятельного продукта для управления задачами
- **Связанные решения**: нет

## Контекст

Продукт должен работать автономно на **Raspberry Pi** и обслуживать пользователей с компьютера и телефона через единый веб-интерфейс.

Ключевые требования:

- **Единый веб-клиент** для ПК и телефона (браузер).
- **Нативная ARM-сборка** и контроль ресурсов на стороне сервера.
- **Данные и файлы остаются на сервере пользователя** (локальное хранение).
- **Главный критерий качества**: предсказуемое хранение и синхронизация задач.
- Надёжность через PostgreSQL (WAL, транзакции, MVCC) и регулярное резервное копирование.

## Критерии выбора архитектуры

| Критерий | Почему важен | Как решение ему соответствует |
|---|---|---|
| Нативная ARM-сборка | Raspberry Pi требует эффективного использования CPU и RAM | C++-сервер компилируется нативно под ARM |
| Единый веб-интерфейс | Не дублировать UI для ПК и телефона | Адаптивный браузерный клиент для всех устройств |
| Предсказуемое хранение | Задачи и вложения — ценные данные | PostgreSQL + WAL + транзакции + локальный каталог |
| Синхронизация | Пользователь работает с нескольких устройств | C++ HTTP API как сервис задач и синхронизации |
| Автономность | Данные не должны уходить в облако | Всё хранится на Raspberry Pi пользователя |
| Резервное копирование | Защита от сбоев SD-карты и питания | Регулярные бэкапы БД и вложений на внешний носитель |
| Отсутствие мобильного приложения на старте | Сократить сроки и стоимость первой версии | Веб-интерфейс + HTTP API |
| Расширяемость | Позже можно добавить нативные клиенты | Чёткий HTTP API |

## Решение

1. **Клиенты** — браузер на компьютере и браузер на телефоне используют один адаптивный веб-интерфейс.
2. **Сервер** — Raspberry Pi, нативное C++-приложение, предоставляющее **HTTP API** как сервис задач и синхронизации.
3. **Хранилище**:
   - структурированные данные — **PostgreSQL** с режимом **WAL** и транзакциями;
   - вложения — **локальный каталог** на сервере.
4. **Резервное копирование** — регулярное создание резервных копий БД и вложений.
5. **Мобильное приложение** на первом этапе не создаётся.

## Риски и меры снижения

| Риск | Вероятность | Влияние | Меры снижения |
|---|---|---|---|
| Потеря данных из-за сбоя SD-карты | Высокая | Критическое | Регулярные бэкапы на внешний носитель; рекомендация SSD/USB; проверка восстановления |
| Повреждение БД при сбое питания | Средняя | Высокое | WAL, `synchronous=on/off`, UPS, корректное завершение |
| Конкурентная запись в PostgreSQL | Низкая | Среднее | MVCC, пул соединений, настройка `max_connections`, ограничение одновременных писателей |
| Перегрузка Raspberry Pi | Средняя | Среднее | Профилирование, лимиты, кэширование, отказ от тяжёлых зависимостей |
| Уязвимости HTTP API | Средняя | Высокое | TLS, аутентификация, rate limiting, минимальные права, обновления |
| Сложность C++ и сборки под ARM | Средняя | Среднее | CMake, CI, кросс-компиляция, статические зависимости, тесты |
| Конфликты синхронизации | Высокая | Среднее | Версионирование, `updated_at`, стратегия merge, журнал изменений |
| Ограничения веб-UI на мобильных | Средняя | Низкое | Адаптивная вёрстка, PWA, тестирование на мобильных браузерах |
| Рост объёма вложений | Средняя | Среднее | Лимиты, сжатие, вынос на внешний носитель, очистка |
| Отсутствие push-уведомлений | Высокая | Низкое | PWA push или отложить до следующего этапа |

## Реализация

- **Сервер**: C++17/20, HTTP-библиотека (например, Boost.Beast, cpp-httplib, Drogon), libpqxx. Нативная ARM-сборка.
- **API**: REST/JSON, версионирование `/api/v1`. Сервис задач и синхронизации.
- **БД**: PostgreSQL с `wal_level=replica`, `synchronous_commit=on`, пул соединений (PgBouncer).
- **Вложения**: локальный каталог, путь в БД, контроль целостности.
- **Бэкапы**: systemd timer или cron, `pg_dump` / `pg_basebackup`, копирование вложений, ротация.
- **Веб-UI**: адаптивная вёрстка, при необходимости PWA-манифест.
- **Развёртывание**: systemd unit, сборка под ARM, документация по восстановлению.

## Статус

**Proposed**. После проверки на прототипе и подтверждения производительности на Raspberry Pi решение можно перевести в **Accepted**.
